# 摩氪星图｜阶段性讨论记录

> 日期：2026-11-09  
> 状态：讨论纪要（非最终技术方案）  
> 用途：记录目前已形成的有效沟通，供 M0 后续统筹复核。  
> 存放位置：`0_M0_Yunjing/03_Input`

## 1. 平台整体定位

目前讨论方向是建设一个统一的「摩氪星图」网站/平台，而不是建设几套互不相干的网站。

整体结构：

- 一个统一网站。
- 一个主导航图，作为全局入口和总览。
- 多个可独立扩展的星图模块。
- 一组公共基础能力，供各模块复用。

当前讨论的四个模块：

| 缩写 | 名称 | 当前理解 |
|---|---|---|
| MS | 摩氪记忆星图 | 个人记忆的组织与可视化 |
| KS | 摩氪知识星图 | 知识资产的组织与可视化 |
| HS | 辉星图 | 以真实生活资料为重要来源的个人生活视角 |
| YS | 圆宝星图 | 圆宝相关的独立记忆/认知视角 |

四个模块是当前起点，不构成数量上限。未来允许增加其他星图模块。

## 2. 模块之间的数据关系

目前已明确选择的方向是：**一条记忆可以同时出现在多张星图中，各星图根据自身视角组织和展示它。**

由此形成以下原则：

- 原始数据尽量只保存一份，不因进入多个星图而重复复制。
- 底层建立统一的记忆对象标识（ID）及关系。
- 各星图通过不同的视图、分类和关系组织方式呈现同一批底层对象。
- 允许跨星图关联，不按数据来源把记忆机械切开。
- 可探索统一时间轴，以及跨星图检索和关联能力；具体实现方式仍待设计。

需要区分三个层次：

1. **原始数据层**：照片、视频、聊天记录、Markdown 文件等原始资产。
2. **记忆/知识对象层**：从原始数据中识别、整理出的事件、人物、地点、事实、认知、决策、知识等对象。
3. **星图视图层**：MS、KS、HS、YS 等模块按照各自视角呈现对象及其关系。

## 3. 各模块的数据特点

目前讨论认为，各模块的数据处理路线不必完全相同，但应建立在统一的底层规范之上。

- **KS**：主要面向 Obsidian/OSG 中的 Markdown 知识资产，可利用 YAML、双链、标签、附件和目录结构等信息。原则上保持原始知识文件为权威数据，星图侧负责读取、解析、索引和可视化。
- **HS**：主要面向照片、视频及其他真实生活记录，需要处理 EXIF、时间、地点、人物、事件等多媒体信息。
- **MS**：面向个人完整记忆，包含 AI 对话、思考、决策，也包含生活经历及其背景；不应仅按“AI 数据”与“生活数据”进行割裂。
- **YS**：保留圆宝自身相对独立的记忆/认知组织，同时允许与其他星图建立关联。

以上是当前定位理解，不代表各模块的数据范围和字段已经最终冻结。

## 4. 星图节点与组织方式

针对“节点究竟采用摩氪节点，还是生活、工作、兴趣、技能等分类”的讨论，当前倾向是：

**底层统一节点，上层允许切换不同组织视图。**

初步区分为不同维度：

- **摩氪体系维度**：M0–M9 等体系节点，体现摩氪体系自身的组织结构。
- **生活领域维度**：生活、工作、兴趣、技能等，体现内容所属领域。
- **对象类型维度**：事件、人物、地点、项目、知识等，体现节点本身是什么。
- **关系探索视图**：围绕对象之间的关联自由展开。

这些维度不是同一层级，不宜强行合并成一套互斥分类。

当前建议方向：底层节点具有稳定、统一的 ID；上层可切换不同视图，同一对象可以在不同视图中出现。**这仍是待确认的设计方向，并非最终定案。**

## 5. 公共基础能力与模块差异

平台可以共享的能力包括：

- 节点与关系的统一表达。
- 图谱渲染、缩放、筛选和展开。
- 搜索、时间轴及跨模块关联。
- 节点详情与来源追溯。
- 数据导入、更新、索引和状态管理。

各模块仍可保留自己的数据接入、解析、索引、分类和展示逻辑。概括来说：**一个平台，共享基础能力，多个模块按自身数据特点处理。**

## 6. 元数据与数据清洗加工深度

讨论中确认：基础元数据标准是星图体系的关键基础，数据清洗加工的边界需要继续复核。

此前提出的问题是：现有讨论中的 **P1 加工程度是否足够**。

目前不能直接认定 P1 已经足够，也不能用临时自拟的分级定义替代此前讨论过的 P1 标准。后续应先找回并核对原有 P1 定义，再结合 MS、KS、HS、YS 的数据特点判断：

- 哪些基础元数据必须统一；
- 哪些字段应由模块按需扩展；
- P1 是否足以支持节点生成、关系建立、搜索和星图展示；
- 哪些高阶语义提取或跨源关联可以留到后续阶段。

当前可确认的原则是：统一基础规范，同时允许模块专属字段；不要求所有来源的数据都经过完全相同的加工流程。

## 7. 当前有效共识与待确认事项

### 当前讨论中已明确的方向

1. 建设统一的摩氪星图网站，而不是四套完全独立的网站。
2. 采用一个主导航图和多个独立星图模块的结构。
3. 当前模块为 MS、KS、HS、YS，架构需要支持未来扩展。
4. 一条记忆可以关联并呈现在多张星图中；原始数据不因多视图而重复保存。
5. 区分原始数据层、记忆/知识对象层、星图视图层。
6. 各模块可有不同的数据处理路线，但应共享底层基础规范。
7. 节点组织倾向于多维度、可切换视图，而不是只采用摩氪节点或只采用生活分类。

### 尚未最终确定

1. 节点类型、关系类型及统一元数据字段的正式标准。
2. 之前讨论的 P1 清洗加工标准原文，以及 P1 是否足够。
3. 摩氪节点、生活领域、对象类型等视图的具体交互和切换方式。
4. MS、KS、HS、YS 的最终数据边界及跨图权限规则。
5. 主导航图与各模块之间的具体导航、总览和关联呈现方式。
6. 技术选型、数据索引方案及实施阶段。

## 8. 后续讨论建议

下一步优先找回既有 P1 数据清洗加工标准，以原标准为基础复核，而不是重新创造一套分级体系。随后再确定统一元数据、节点/关系模型和多视图机制。
