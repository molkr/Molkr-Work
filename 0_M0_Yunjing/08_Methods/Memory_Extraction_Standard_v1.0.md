# 通用记忆提取规范

**版本：** V1.0  
**维护节点：** M0｜云京  
**适用范围：** 摩氪体系中的个人、宠物及其他重要主体的历史记忆提取与结构化整理  
**文件定位：** M0 方法库中的通用方法规范，可供 M0–M9 及不同 AI 平台复用。

---

## 一、目的与适用原则

本规范用于将分散在 ChatGPT、DeepSeek、豆包及其他平台中的历史对话，转化为可保存、可核验、可迁移、可持续更新的结构化记忆资产。

本规范不是某个主体的专属档案，也不是简单的聊天总结。提取对象可以是用户本人、宠物、家人、朋友或其他重要主体；应根据对象特点调整具体内容，但底层字段、证据标准和处理流程保持一致。

**核心原则：尽量保留有价值的原始信息，以事实为基础，保留时间与来源，明确不确定性，避免总结造成的信息损失。**

## 二、总体处理流程

建议按以下顺序执行：

1. **数据获取：** 优先获取平台提供的完整历史导出文件；无法导出时，再从专属对话中分批提取。
2. **原始数据保全：** 原始导出文件只读保存，不在原件上直接修改；记录来源平台、导出时间、文件名和覆盖范围。
3. **数据解析：** 识别会话、消息、角色、时间戳、附件及可用的消息标识；保留原始顺序。
4. **对象筛选：** 定位与提取对象有关的会话和消息。不得仅凭标题判断，必要时结合正文核验。
5. **记忆提取：** 按本规范分类，拆分为可独立理解的记忆条目。
6. **交叉核验：** 对比不同平台、不同会话及原始消息；识别重复、冲突、遗漏和推测。
7. **结构化交付：** 输出记忆档案、事件时间线、待确认清单和来源索引。
8. **审核与入库：** 用户审核重要事实和敏感内容后，再纳入正式记忆库；保留版本和修订记录。

如原始数据可直接解析，应优先从原始数据提取，不要先让模型概括后再把概括当作原始事实。AI 对话提取可作为补充、解释和查漏方式。

## 三、记忆分类框架

以下类别是通用分类框架，不要求每个对象都填满。按实际内容使用，不适用的类别可省略。

### 01｜主体档案
- 名称、称呼、身份及基本信息
- 外貌、外在特征及可识别特征
- 重要关系及关系变化
- 信息有效时间；可能变化的资料不得默认永久有效

### 02｜长期特征
- 相对稳定的性格、习惯和行为模式
- 喜好、偏好、厌恶及选择倾向
- 能力、特长、需求和日常规律
- 区分长期稳定特征与短期状态

### 03｜经历与事件
- 重要经历、成长阶段和关键事件
- 事件发生时间、地点、经过、参与者及结果
- 重要转折、决定和后续影响
- 对事件的记忆应尽量保留具体细节，不只保留结论

### 04｜日常记录
- 日常生活、互动、行为和变化
- 有长期观察价值的细节
- 反复出现的现象及其时间跨度
- 具有代表性或值得留存的普通瞬间

### 05｜重要信息与管理
- 照料、健康、生活管理或其他与对象相关的重要信息
- 已确认的安排、计划、约定和决定
- 正在持续的事项及其当前状态
- 记录信息的时间，避免把过期状态当作现状

### 06｜情感与意义
- 用户明确表达的感受和态度
- 重要情感连接、关系变化和纪念意义
- 对用户或主体有特殊意义的经历
- 必须区分用户明确表达与 AI 对情感的解释

### 07｜待确认与冲突
- 时间、人物、地点或事实不明确的信息
- 不同会话或平台之间互相矛盾的信息
- 只有 AI 推测、缺少原始依据的信息
- 需要用户补充、确认或纠正的事项

### 08｜记忆索引
- 关键词、别名、相关人物、地点和事件
- 关联照片、视频、文件或其他资料的线索
- 主题标签及跨类别关联
- 索引用于检索，不应替代原始记忆内容

## 四、单条记忆的数据结构

每条记忆应尽量表达一个明确事实、观察、经历或决定，并能脱离上下文独立理解。

建议字段：

| 字段 | 要求 |
|---|---|
| 记忆编号 | 稳定且唯一；合并时保留旧编号映射 |
| 记忆内容 | 清晰、具体、避免含糊代词 |
| 主体 | 记忆涉及的主体 |
| 记忆类别 | 使用第三章分类，可多选 |
| 发生时间 | 日期或时间范围；未知则明确标注未知 |
| 时间精度 | 精确日期／大致日期／时间段／未知 |
| 相关人物与对象 | 事件参与者及关联对象 |
| 地点 | 明确地点；未知则不推断 |
| 来源依据 | 平台、会话标题或 ID、消息 ID／时间戳／原文定位 |
| 信息性质 | 明确事实／用户陈述／他人陈述／AI 推测／待确认 |
| 置信状态 | 已核实／单一来源／存在冲突／待确认 |
| 重要程度 | 高／中／低，并说明重要原因（如有） |
| 有效状态 | 当前有效／历史状态／已变化／未知 |
| 关联记忆 | 相关记忆编号、事件或媒体线索 |

### 记录要求

1. 保留原意和关键细节，不为追求简短而删除有价值的信息。
2. 将不同事实拆成独立条目；同一事件的多个细节可通过关联编号连接。
3. 明确区分“发生时间”和“对话提及时间”。
4. 对无法确定的日期，不得根据上下文擅自补成精确日期。
5. 用户的明确陈述、AI 的归纳和 AI 的推测必须区分。
6. 对重要原话，可保留短引文或原文定位；不要用改写内容冒充原话。
7. 同一事实被多次提及时，可合并为一条并保留全部来源；不同时间发生的相似事件不得误合并。
8. 重要程度用于排序，不代表事实真实性或置信度。

## 五、时间线与事件记录

除单条记忆外，应建立重要事件时间线。每个事件建议包含：

- 事件编号及标题
- 发生时间或时间范围
- 事件经过
- 参与主体
- 事件结果与后续影响
- 关联记忆编号
- 来源依据及核验状态

时间线按发生时间排序。时间未知或只有大致范围的事件应单独标注，不得伪造精确顺序。

## 六、来源、证据与冲突处理

### 来源优先级

1. 可定位的原始用户消息、原始附件或原始记录。
2. 同一平台的完整会话导出数据。
3. 其他平台中独立记录的相关对话。
4. AI 根据历史内容生成的结构化提取结果。
5. 无法定位来源的模型记忆或推断。

来源优先级是核验时的参考，不意味着高优先级来源必然正确。对重要事实应尽可能交叉验证。

### 冲突处理

- 不擅自选择一个版本覆盖其他版本。
- 分别保留冲突内容、各自来源和时间。
- 判断是否可能是状态变化、记忆误差、时间口径不同或主体混淆。
- 无法判断时标记“存在冲突，待确认”。
- 用户确认后记录最终结论，同时保留必要的历史修订线索。

## 七、去重与合并规则

1. 先判断是否描述同一事实或同一事件，再进行合并。
2. 语义相似不等于事实相同；不得只按关键词去重。
3. 合并后保留所有有效来源，不丢失独有细节。
4. 对重复记录中的时间、地点、人物差异进行核对。
5. 无法确定是否重复时，先保留为独立条目并加入待核验清单。
6. 不得为了减少条数而牺牲记忆完整性。

## 八、不同对象的适配

通用框架保持一致，提取重点按对象调整：

- **个人：** 成长经历、职业与生活变化、重要关系、价值观、偏好、决策和长期计划。
- **宠物：** 基本特征、成长过程、性格习惯、日常互动、照料信息、重要事件和情感连接。
- **其他人物：** 基本档案、关系、共同经历、明确表达过的偏好及重要事件。

涉及健康、身份、家庭关系等敏感信息时，应遵循最小必要原则；只提取任务确实需要且用户有权整理的内容，并谨慎控制共享范围。

## 九、原始数据与文件交付

建议每次提取至少形成以下交付物，规模较小时可合并为一个 Markdown 文件：

1. **原始数据说明：** 来源平台、导出时间、文件清单、数据覆盖范围、解析限制。
2. **结构化记忆档案：** 按分类保存的记忆条目。
3. **重要事件时间线：** 按发生时间组织。
4. **待确认与冲突清单：** 不确定、冲突、缺少来源或需要用户判断的内容。
5. **提取报告：** 提取条数、类别分布、来源覆盖、重复合并情况、无法解析内容和已知遗漏。

原始导出文件应与加工结果分开保存。不得把加工后的文件覆盖原始数据。若平台导出包含附件，应记录附件与消息的关联；无法读取的附件要明确列出。

## 十、质量检查与验收标准

交付前至少检查：

- 是否说明实际读取的数据范围，是否存在历史缺失或截断。
- 是否保留用户消息与 AI 消息的角色区别。
- 是否保留消息顺序、可用时间戳及会话标识。
- 是否区分事件发生时间与提及时间。
- 是否把推测、建议或 AI 生成内容误记为用户事实。
- 是否存在无来源的重要结论。
- 是否错误合并相似但不同的事件。
- 是否保留冲突和待确认事项。
- 是否保留高价值的具体细节，而非只输出概括性总结。
- 是否记录解析失败、附件缺失及其他限制。

**验收底线：来源可追溯、事实与推测分离、时间口径清楚、冲突不被掩盖、原始数据不被破坏、遗漏和限制如实说明。**

## 十一、可复用的 AI 提取任务提示词

以下提示词可用于 ChatGPT、DeepSeek、豆包及其他 AI。使用时只需替换提取对象和数据来源。

---

你正在执行一次历史记忆提取任务。

**提取对象：**【填写主体名称】  
**数据来源：**【填写平台、会话或导出文件】  
**任务目标：** 将历史交流中有长期保存价值的信息提取为可核验、可迁移、可持续更新的结构化记忆资产。

请遵循以下要求：

1. 优先依据可访问的原始历史数据，不要只凭当前对话上下文或模型印象回忆。
2. 尽可能覆盖指定范围内的全部相关历史，不只提取最近内容。
3. 按《通用记忆提取规范》中的八类结构整理；不适用的类别可省略。
4. 每条记忆独立表达，尽可能记录发生时间、相关主体、来源依据、信息性质和核验状态。
5. 严格区分用户陈述、他人陈述、AI 归纳、AI 推测和待确认信息。
6. 不编造事实，不擅自补全时间，不把未获用户确认的 AI 建议写成既定决定。
7. 对重复信息谨慎合并，并保留合并后的全部来源；对冲突信息并列保留。
8. 尽量保留具体细节、重要原话和有意义的普通瞬间，不要只写概括性总结。
9. 如无法访问全部历史、无法读取附件或存在上下文截断，明确报告实际覆盖范围和限制。
10. 内容较多时分批输出，保持编号连续，并说明批次范围；不得为了缩短篇幅擅自删除记忆。

**交付内容：**
- 结构化记忆档案
- 重要事件时间线
- 待确认及冲突清单
- 提取统计与数据覆盖说明

本任务是历史数据提取，不是重新创作主体介绍，也不是要求你根据常识补全主体信息。请先说明可读取的数据范围，再开始提取。

## 十二、版本维护

- 本规范作为 M0 方法库中的通用标准独立维护。
- 后续可根据实际提取经验修订版本，但不得静默改变字段含义。
- 新增字段应说明用途；字段调整应保留兼容或迁移说明。
- 圆宝、个人或其他主体的具体档案属于数据成果，不应反向混入本规范。
- 任何平台专属导出格式、解析脚本和平台操作说明，应作为独立配套资料维护，不将平台差异写死在通用规范中。

**最终原则：原始数据可追溯，记忆条目可核验，结构跨平台通用，结果可持续维护。**
