# M91B V1 技术方案｜审查输入整理稿

> 来源说明：本文件依据当前对话中用户提供的「M91B 记忆星图 · 技术方案 v1」内容整理，供独立审查使用。它不是原始完整方案文件的逐字副本；如取得原始文件，应以原件补充或替换本整理稿。

## 一、定位
摩氪记忆库（P001）的可视化投影层，将已建成的记忆数据转化为可探索的本地星图。

## 二、数据来源
1. `t04_index.db`（SQLite + FTS5）：约 53 张会话卡、192 张段卡、203 个实体；DeepSeek 约 54 个会话、556 万字，map-reduce 已验收。
2. T03 照片主档 JSONL：约 1540 张照片已粗筛（留／废／疑、标签、日期）；原始副本库为 `00_Raw`。
3. 摩氪体系预置本 V3.7：M0–M9 十节点及微摩氪架构。

## 三、V1 生成方式
Python 从源数据导出节点、边和时间密度 JSON，并嵌入 HTML 模板，生成 `记忆星图.html`。数据更新时重跑脚本；AI 升级时重新计算投影。核心原则为“底账永不重建、元数据全部可再生”。

## 四、主要视图与交互
- 星云主视图：力导向图；节点包括实体、会话卡、照片组；关系包括归属、提及、时间相邻；M0–M9 为一级星系枢纽，微摩氪为二级。
- 时间轴：照片（约 2020-03 至 2024）与对话（约 2026-08 起）双通道密度同轴展示。
- M 系导航：十个节点及计数，点击后聚焦。
- 点击节点显示详情、来源检查和 L1 原件路径回指。
- 顶部检索框复用 `t04_query` 的 FTS5 逻辑。
- 模块开关控制数据源、视图和显示项；模块可自定义，配置拟使用 localStorage。

## 五、V1 技术设想
- 原生 JavaScript + 内嵌数据，零框架、零服务端、无网络请求。
- 图布局候选为 vendored D3-force。
- 单文件 HTML，支持 `file://` 双击打开，整个文件夹拷贝即用。
- 体积目标约 2MB；超出后考虑按星系拆分文件。
- 无语义边；未来可考虑 sqlite-vec。
- 曾借鉴“记忆星海／大肥鱼”DeepSeek QQ 机器人插件的来源检查、遗忘模拟、相机环视交互创意，不引入其底座。

## 六、已提出的验收目标
- Chrome／Edge 中通过 `file://` 双击打开。
- 约 54 个会话与 1540 张照片能够完整渲染且无明显卡顿。
- 检索、高亮、过滤、M 星系聚焦正确。
- 复制到其他电脑仍可打开。
- 数据源更新后，重新生成可自动更新投影。

## 七、后续已确认的 V2 约束（审查时须纳入）
- 运行双模式：离线独立模式 + 本地服务模式。
- 当前规模优先，同时预留百万级扩展能力。
- AI 双引擎：本地 AI + 云端 AI。
- 所有 AI 分析结果先进入审核区，用户确认后才写入正式记忆元数据。
- 原始资料受保护，云端调用最小化且需授权。
- AI 能力不应成为基础星图浏览和离线运行的必要条件。
