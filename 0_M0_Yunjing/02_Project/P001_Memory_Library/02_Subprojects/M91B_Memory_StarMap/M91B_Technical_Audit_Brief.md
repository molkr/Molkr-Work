# M91B Memory StarMap｜V2 独立技术架构审计简报

本任务是独立技术架构审计，不是开发任务，也不是要求审查者为现有方案背书。请先独立判断方案是否成立，主动寻找可能推翻当前设计的证据、缺陷和更优替代方案。

**本轮只交付审计报告与建议，不修改代码、不部署服务、不启动开发。**

## 2. 项目背景
M91B 是 P001「摩氪记忆库」下的记忆可视化与智能交互子项目。它负责把已整理的照片、对话及其他记忆数据投影为可探索的星图，并逐步支持检索、关联分析、智能问答和记忆洞察。

当前已有数据基础（来自项目方案提供的信息，审查时应核对口径）：
- SQLite + FTS5 数据库：约 53 张会话卡、192 张段卡、203 个实体。
- 对话来源：约 54 个 DeepSeek 会话、约 556 万字，已完成 map-reduce 提取。
- 照片主档 JSONL：约 1540 张照片已粗筛并带有留/废/疑、标签和日期信息。
- 原始照片副本保存在 00_Raw。
- 摩氪体系预置本包含 M0–M9 十个一级节点及微摩氪细分结构。

以上数字是当前方案所述的规模，不应直接视为已经独立验证的事实。请指出审计前仍需取得哪些数据、样本或文件。

## 3. 已确认的产品与架构约束
以下是用户已明确选择的方向，不是审查者可擅自改写的既定事实；如认为存在更优替代方案，请单独列出依据、代价和迁移影响：
1. 运行方式：离线独立模式 + 本地服务模式。
2. 规模定位：当前规模优先，同时预留百万级扩展；不要求当前一次性承载百万节点。
3. AI 运行策略：本地 AI + 云端 AI 双引擎。
4. AI 写入策略：所有 AI 分析结果先进入审核区，用户确认后才能写入正式记忆元数据。
5. 原始照片、原始对话和原始文件必须受到保护；AI 不得直接修改原始资料。
6. 本地数据自主、可迁移；模型供应商可替换；云端 AI 不能成为星图基础浏览和离线运行的必要条件。
7. 项目先完成架构复核，再决定实施；本简报不授权直接开工。

## 4. V1 方案的主要设计
当前 V1 提议包括：
- 单文件 HTML，零框架、零服务，支持 file:// 双击打开；整个文件夹可拷贝迁移。
- Python 从 SQLite、照片 JSONL 和摩氪体系结构生成 JSON 投影数据并嵌入 HTML；数据更新时重跑生成脚本。
- 图谱视图：节点包括实体、会话卡、照片组；关系包括归属、提及、时间相邻；M0–M9 作为一级枢纽，微摩氪为二级。
- 时间轴：照片与对话双通道密度展示。
- M 系导航：十个一级节点及计数，支持点击聚焦。
- 交互：节点详情、来源回指、检索、模块开关和配置。
- 图形技术候选：原生 JS + 内嵌数据，D3-force 用于图布局；曾提出 Sigma.js + Graphology 作为升级候选。
- 数据检索：SQLite/FTS5 是底层检索来源；离线模式需解决浏览器无法直接按普通网页方式访问本地 SQLite 的限制，本地服务模式可由 Python 查询。
- 规模策略：分层数据、稳定 ID、局部加载、聚合与展开，避免浏览器一次性渲染百万节点。
- 未来 AI：本地 AI 与云端 AI 双引擎，通过统一接入层、任务路由、隐私策略和权限控制调用；AI 结果先入审核区，用户确认后才写正式元数据。

## 5. 重点审计问题
请逐项审查，并主动补充遗漏问题：

### A. 产品与运行架构
- 离线独立模式与本地服务模式是否有清晰、可实现的能力边界？
- 单文件 HTML、自包含投影数据与可维护性、体积控制之间是否冲突？
- file:// 环境下的浏览器限制、存储持久化、模块加载与检索能力是否处理正确？
- 是否应采用渐进增强、降级策略或不同入口？

### B. 图谱与可视化技术
- Sigma.js、Graphology、D3-force 的组合是否合适？是否存在更稳妥或更轻量的替代方案？
- 当前规模下是否真的需要 WebGL？Canvas、SVG、Cytoscape.js 等选项的取舍是什么？
- 时间轴是否适合原生 Canvas，还是应采用成熟组件？
- 图谱布局是否需要预计算、增量布局或缓存？

### C. 数据架构与百万级扩展
- SQLite + FTS5 与离线投影数据的职责边界是否合理？
- 节点、边、实体、事件、照片组、会话卡、段卡应如何分层？
- 如何实现稳定 ID、数据版本、增量更新、局部加载、分页、聚合、索引和来源追溯？
- 如何避免“百万级预留”演变为过度设计，或产生无法兑现的性能承诺？
- 时间相邻关系与语义关联如何区分，如何记录证据，如何避免错误关联？

### D. AI 双引擎
- 本地 AI 与云端 AI 的统一接口、模型适配、任务路由和失败降级如何设计？
- 哪些任务适合本地，哪些任务可调用云端？是否需要用户可控的自动路由？
- 如何保护 API Key，如何处理模型不可用、超时、成本、速率限制和模型替换？
- 如何做到云端默认最小化数据外发、逐任务授权，并明确告知发送的数据范围？
- 本地硬件约束下，哪些模型与任务可行？不要假设本地可运行大型多模态模型。

### E. 审核与写入安全
- 审核区是否应作为独立数据层或独立表结构？
- 如何保存 source_id、证据、模型与版本、提示词版本、分析时间、审核状态和审核者操作？
- 如何防止重复写入、错误关联、字段污染和并发冲突？
- 如何支持拒绝、修改后通过、版本追踪、撤销和重新生成投影？
- 如何保证 AI 结果不会绕过审核区直接写入正式记忆元数据？

### F. 工程实施与维护
- Python 服务、目录结构、依赖、打包和启动方式是否足够简单？
- 双模式是否会造成两套逻辑分叉？如何共享业务逻辑和测试？
- 如何设计自动化测试、样本测试、性能测试和故障降级？
- 哪些能力应该延后，哪些必须在第一阶段建立？
