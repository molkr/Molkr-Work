# 限时福利自动监测与提醒系统

- ID：M9_001
- 创建时间：2026-11-02
- 来源：M0 云京
- 主关联节点：M9 钪铼（AI 协作与超级外脑）
- 次关联节点：M3 拓芯（事业与收入、资源利用）
- 状态：待评估
- 关键词：限时福利、免费额度、活动监测、信息抓取、实时提醒、自动化

## 原始灵感

例如 ZCode 最近推出的限时免费 Token 活动：在指定时间开放领取，之后只能在特定时段使用。类似这种比较大的平台活动、免费福利和限时优惠，能否通过一个项目自动抓取、监测，并在活动开放或即将开始时实时提醒我，避免错过？

## 项目初步定位

建立一个互联网限时福利与活动情报监测系统。自动发现、收集、核实和筛选有价值的活动信息，并根据活动时间、领取条件和适用范围向用户发出提醒。

## 关注的信息类型

- AI 平台免费 Token、模型体验额度、免费调用窗口
- AI 编程工具、Agent、开发工具的限时福利
- 软件和云服务的免费试用、赠送额度、优惠活动
- 有明确领取期限、名额限制或开始时间的重大活动
- 其他用户可能实际受益、值得关注的限时福利

## 初步功能设想

1. 多来源监测：官方公告、产品官网、社交媒体、社区及可信活动聚合站。
2. 自动识别：识别活动名称、福利内容、领取时间、使用时间、截止时间、适用人群和领取方式。
3. 信息核验：优先查官方来源；对社区线索进行交叉核实，标明来源、发布时间和可信程度。
4. 去重与更新：识别同一活动的重复发布、时间变更、名额耗尽和活动结束。
5. 智能筛选：按用户关注的平台、福利类型、价值和可参与条件过滤。
6. 分级提醒：活动发布提醒、即将开放提醒、领取窗口开启提醒、截止前提醒。
7. 活动归档：保存活动记录及状态，避免把过期活动误报为仍有效。

## ZCode 示例（用于说明需求）

截至 2026-11-02 的公开信息中，ZCode 曾发布每日 3 亿 GLM-5.3-Flash Token 福利：北京时间 19:00 起领取，23:00 至次日 09:00 使用。该例说明系统不仅要识别“免费额度”，还要准确区分领取时间与实际可使用时间。具体活动是否持续有效，仍须以官方当日公告和客户端实际显示为准。

## 关键设计原则

- 不能只抓取信息，还必须核实真实性和时效性。
- 明确区分“可领取时间”“可使用时间”“截止时间”。
- 不把免费额度、试用额度、订阅权益和可导出的 API Token 混为一谈。
- 只提醒真正符合用户条件、具有实际价值的活动，避免通知泛滥。
- 优先采用低成本、可长期运行的实现方式。
