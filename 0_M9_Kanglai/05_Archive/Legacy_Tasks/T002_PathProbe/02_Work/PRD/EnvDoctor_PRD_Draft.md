## 1. 项目背景

本项目源于任务 T002_PathProbe：一款探测本机 PATH、核心命令路径与版本、相关环境变量的 PowerShell 脚本，已有可运行原型（V1/V2）及符合原始任务规格的探测报告。

2026-11-02 代码诊断发现的主要问题（均有产出物实证）：

- V1 脚本未处理 `wsl.exe` 的 UTF-16LE 输出，导致 `pathprobe_report.md` 被写入含 NUL 字节的非法 UTF-8 内容，文件实际已损坏；V2 输出中同一问题表现为乱码（「WSL Hr,g:」实为「WSL 版本:」）。
- 输出路径硬编码（`D:\0_M9_Kanglai\...`），换机或换目录即失效。
- V1/V2 双脚本并存，命令与环境变量清单重复硬编码，存在漂移风险。
- 部分扩展探测无超时保护；Docker daemon 未运行时误报为 0 容器；`where.exe` 首命中可能为不可执行项（如 Microsoft Store 存根、无扩展名脚本）。
- 每条命令使用 Start-Job 探测版本，整体耗时约 20 秒。

竞品扫描结论：生态专用 doctor（flutter/brew/cargo 等）与 PATH 编辑类工具（PathRight 等）各自存在，但「Windows 整机开发环境只读体检」位置空缺；微软 winget configure / DSC v3 为声明式装机方向，缺少装机前体检、装机后验收、日常漂移审计等反向审计环节，本产品以此作为生态位叙事。

与 WinMew（T013）的关系经确认：**独立产品、松耦合协同**——受众、领域、形态、操作哲学均不同，不合并；仅在 JSON 快照 schema、「诊断开处方、不代执行」哲学及生态位叙事三个点上保持对齐。

**2026-11-02 AC 审核结论（已并入本稿）：** 产品方向值得继续；保留三大核心能力（probe / check / diff）；首版收缩范围；建立统一诊断等级与产品级数据标准（JSON Schema 先行）；建立可执行的诊断规则和验收标准后，再进入技术方案复核。用户已确认其中两项关键决策（见 §2、§6.1）。

## 2. 产品定位

**已确认（用户 2026-11-02 拍板）：** EnvDoctor 是一款**面向开发者、AI 工站使用者和 AG 执行环境的专业诊断工具**——Windows 开发环境只读体检 CLI。不做面向普通用户的大众体检工具（该方向属于 WinMew 的产品领地）。

单文件、零依赖、终端交互，围绕三个动词组织：

- **probe（探测）**：盘点 PATH、命令、环境变量，产出 Markdown 报告与 JSON 快照；
- **check（诊断）**：对探测结果按统一四级诊断下判断，每条结论附原因、影响面与处理建议；
- **diff（对比）**：将当前快照与历史快照做基础对比，标注新增、移除与变更。

**产品原则（已确认，随 AC 审核采纳）：**

1. 只读，不擅自修改系统——不写环境变量、不安装软件、不清理文件、不自动修复。
2. 不联网。
3. 不依赖第三方运行库。
4. 给出问题原因和处理建议，但不代为执行。
5. 尽可能兼容 Windows PowerShell 5.1 与 PowerShell 7。

只读红线与源任务 T002 的「不修改、不安装」限制同源，也是与 PATH 编辑类工具及 WinMew「管理辅助」方向的产品分界。

「EnvDoctor」为暂定名，品牌定案与查重待确认。

## 3. 产品目标

**首版目标（已确认）：** 让 Windows 开发者快速获得一份**可信、完整、可读**的开发环境体检报告。

**长期愿景（不构成版本承诺）：** 逐步发展为 Windows 开发环境诊断平台，扩展方向包括 Python / Node.js / Java 运行环境、Git / GitHub / SSH 工具链、Docker / WSL、NVIDIA 驱动 / CUDA、Ollama / 本地 AI 模型运行环境、AI Agent 所需的本机执行环境。Baseline（机器的 requirements.txt）与装机/迁移场景随该愿景在后续版本讨论。

成功标准定位为「在对的时刻有用」（排障交付、环境审计、CI/AG 前置检查）；具体可衡量指标待确认。

## 4. 目标用户

- **已确认：** 专业向用户——开发者、运维、AI 工作站使用者（Ollama / CUDA / Docker 组合）、使用 AG 自动化工作流的用户。
- 明确不优先面向：不熟悉命令行的普通用户（属于 WinMew 的目标领地）。
- 首版典型场景：环境审计与排障（输出快照交付他人）、CI 或 AG 任务执行前的环境前置检查。装机与迁移场景随 Baseline 后置。
- 用户技术熟悉度假设：能用 PowerShell 执行单条命令；具体画像待确认。

## 6. 功能需求

### 6.1 功能清单

**首版范围（已确认，按 AC 建议收缩）：**

1. **环境扫描**：PATH（用户/系统含来源）、命令路径与版本、环境变量。
2. **环境诊断**：识别失效路径、命令解析异常（含存根遮蔽）、组件异常（如 Docker daemon 未运行）、资源水位（磁盘）等；四级诊断，附原因与建议。
3. **体检报告**：输出 Markdown（人读）与 JSON（机读，schema 先行）。
4. **历史对比**：基础快照比较（与上次快照的新增/移除/变更）。

Baseline、处方层（winget 安装命令生成）、AI 工作站专项均移出首版。

- 已确认的输入清单来源：沿用 T002 规格——15 个核心命令、7 个环境变量、密钥类只记存在性；发布版是否扩充清单待确认。
- 详细的逐项需求条目在诊断规则细则（§9.5）定稿后补写。

### 6.2 用户场景与使用流程

首版场景（讨论中，非最终定案）：

- 审计场景：`check` 终端输出四级诊断结论；`probe` 留档完整报告。
- 排障交付场景：`probe` 生成报告，直接发给他人或贴入 issue。
- 自动化场景：`check -Json` 与退出码约定（讨论中）供 CI/AG 调用。

后置场景（随 Baseline，v2 讨论）：装机处方（缺失项 + winget 命令文本）、换机迁移（老机快照 vs 新机 diff）。

### 6.3 输入、处理与输出

- 输入：命令行参数（讨论中）：动词 probe/check/diff、`-OutputPath`、`-TimeoutSec`、`-Compare` / `-With`；可选外置配置文件覆盖默认探测清单。
- **数据标准（已确认原则：JSON Schema 先行）**：JSON 快照是整个产品的数据基础——Markdown 是给人看的渲染层，JSON 是给程序使用的数据层；未来 diff、Baseline 及 AI Agent 自动分析均建立在统一数据结构上。Schema（含 `schema_version`）应尽早定稿，而不是功能做完再补。
- 处理：探测引擎（原始字节捕获 + 编码嗅探 + 超时控制 + 命中择优）→ 数据层（统一结构）→ 渲染层（终端 / Markdown / JSON 三层分离）。
- 输出：终端四级诊断摘要；Markdown 报告（路径表格含来源列、命令表格含状态列、环境变量表格，对齐 T002 规格的中文状态用词）；JSON 快照（字段英文稳定，供 AG/程序解析及 WinMew 未来消费）。

### 6.4 异常情况与边界条件

以下各项均有诊断实证或已知技术风险，属发布前必须处理项：

- `wsl.exe` 等输出 UTF-16LE 的命令：统一以原始字节捕获后按 NUL 特征嗅探解码（已实证当前 V1/V2 均存在此缺陷）。
- 探测超时：所有 `--version` 及扩展探测（pip / npm / docker）统一超时保护，超时标注 [超时] 而非挂死。
- Docker 三态区分：未安装 / 已安装但 daemon 未运行 / 运行中，避免误报 0 容器。
- `where.exe` 命中择优：优先 .exe / .cmd；对无输出且非零退出的命中（如 Store 存根，实测退出码 49）自动尝试下一命中。
- PowerShell 兼容性：需在 Windows PowerShell 5.1 与 PowerShell 7 下行为一致（含 `Out-File` 编码差异、`.cmd` 调用差异）。
- 失效路径检测需绕开 `Test-Path -IsValid` 对非法字符（通配符、引号）判断不可靠的已知问题（PowerShell issue #21112）。
- **诊断升级需证据原则**：多版本运行环境共存本身常见且常无害，默认记「提示」；仅当获得冲突证据（存根遮蔽真实命令、优先级异常、解析结果无法解释、影响项目运行）时升级「警告/异常」。

### 6.5 功能优先级与版本归属

| 层级 | 内容 | 性质 |
|---|---|---|
| 发布门槛 | L1 编码修复、L2 配置统一与路径自适应、L3 输出合规、README/LICENSE/示例 | 不完成不发布 |
| 首版核心 | 四级诊断规则 + 基础 diff + JSON Schema 定稿 | 首版范围（已确认） |

## 7. 非功能需求

- 产品原则（已确认）：只读；不联网；不依赖第三方运行库；不安装、不清理、不自动修复；给出问题原因和处理建议；兼容 Windows PowerShell 5.1 与 PowerShell 7。
- 性能：版本探测从现有 Start-Job 方案约 20 秒降至秒级（改用 Start-Process 原始进程并发等待）；具体指标待实现后实测确认。
- 稳定性：任何单条探测异常不得中断整体流程；全部探测有超时上限。
- 安全与隐私：密钥类变量只记存在性不记值（沿 T002 约束）。
- 易用性：下载即用（单文件）；报告语言（中文为主 / 双语 / 英文优先）待确认。
- 兼容性：Windows 10/11；PowerShell 5.1 与 7 双兼容；最低支持版本待确认。
- 日志与诊断：约定退出码（讨论中）；关键异常在报告中标注原因而非静默吞掉。
- 安装、升级与分发：主渠道 GitHub Releases 提供单文件；辅渠道 PowerShell Gallery（Install-Script）；明确不做 exe 打包（杀软误报风险）；不申请 winget 收录（首版）。

| 项目 | 当前信息 |

| 安装包与发布方式 | 单文件脚本；GitHub Releases 为主渠道，PSGallery 为辅渠道；不做 exe 打包 |

技术选型延续现有原型（PowerShell），不因发布而更换语言或引入运行时依赖；如后续需求超出 PowerShell 能力再行评估。
