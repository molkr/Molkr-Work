## 1. 项目背景

本项目源于任务 T002_PathProbe：一款探测本机 PATH、核心命令路径与版本、相关环境变量的 PowerShell 脚本，已有可运行原型（V1/V2）及符合原始任务规格的探测报告。

2026-11-02 代码诊断发现的主要问题（均有产出物实证）：

- V1 脚本未处理 `wsl.exe` 的 UTF-16LE 输出，导致 `pathprobe_report.md` 被写入含 NUL 字节的非法 UTF-8 内容，文件实际已损坏；V2 输出中同一问题表现为乱码（「WSL Hr,g:」实为「WSL 版本:」）。
- 输出路径硬编码（`D:\0_M9_Kanglai\...`），换机或换目录即失效。
- V1/V2 双脚本并存，命令与环境变量清单重复硬编码，存在漂移风险。
- 部分扩展探测无超时保护；Docker daemon 未运行时误报为 0 容器；`where.exe` 首命中可能为不可执行项（如 Microsoft Store 存根、无扩展名脚本）。
- 每条命令使用 Start-Job 探测版本，整体耗时约 20 秒。

用户随后确认产品方向：**在原型基础上做成可发布版本**。竞品扫描结论：生态专用 doctor（flutter/brew/cargo 等）与 PATH 编辑类工具（PathRight 等）各自存在，但「Windows 整机开发环境只读体检」位置空缺；微软 winget configure / DSC v3 为声明式装机方向，缺少装机前体检、装机后验收、日常漂移审计等反向审计环节，本产品以此作为生态位叙事。

与 WinMew（T013）的关系经确认：**独立产品、松耦合协同**——受众（开发者 vs 大众用户）、领域（开发环境 vs 软件资产与运行态）、形态（CLI vs 大概率 GUI）、操作哲学（只读 vs 管理辅助）均不同，不合并；仅在 JSON 快照 schema、「诊断开处方、不代执行」哲学及生态位叙事三个点上保持对齐。

## 2. 产品定位

**当前讨论方向：** 一款面向 Windows 平台的开发环境只读体检 CLI 工具。单文件、零依赖、终端交互，围绕三个动词组织：

- **probe（探测）**：盘点 PATH、命令、环境变量，产出 Markdown 报告与 JSON 快照；
- **check（诊断）**：对探测结果下判断，输出绿/黄/红结论与健康分；空环境时给出缺失项处方（生成 winget 安装命令文本，不执行）；
- **diff（对比）**：将当前快照与历史快照对比，标注新增、移除与变更。

**只读红线（讨论中，建议作为产品根本约束）：** 工具只观察、诊断、建议，永不修改系统——不写环境变量、不安装软件、不清理文件。该约束与源任务 T002 的「不修改、不安装」限制同源，也是与 PATH 编辑类工具及 WinMew「管理辅助」方向的产品分界。

「EnvDoctor」为暂定名，品牌定案与查重待确认。

## 3. 产品目标

当前讨论方向（按用户环境生命周期组织）：

- **装机阶段**：帮助空环境用户明确「缺什么、装什么」，将安装清单以 winget 命令文本形式给出（处方层）。
- **迁移/重装阶段**：老机器的 probe 快照作为新机器的基线，diff 生成差异清单（「你比老机少了什么」）。
- **日常审计阶段**：为环境复杂用户发现失效 PATH 条目、命令多版本冲突、存根遮蔽、环境漂移。

成功标准定位为「在对的时刻有用」（装机、排障、交接、CI 前置检查），而非以 star 数为目标；具体可衡量指标待确认。

## 4. 目标用户

- 主要群体（讨论中）：开发者、运维、AI 工作站使用者（Ollama / CUDA / Docker 组合）、使用 AG 自动化工作流的用户。
- 明确不优先面向：不熟悉命令行的普通用户（该人群属于 WinMew 的目标领地）。
- 典型场景：新机装机、系统重装/换机迁移、排障时输出环境快照交付他人、CI 或 AG 任务执行前的环境前置检查。
- 用户技术熟悉度假设：能用 PowerShell 执行单条命令；具体画像待确认。

## 6. 功能需求

本章节用于逐项记录已确认的功能需求。下列小节中标注「讨论中」的内容未经最终确认，不补写未经确认的详细规则。

### 6.1 功能清单

- v1 收敛范围（讨论中）：probe（编码修复 + 可移植 + 输出合规）、check（四类规则 + 处方）、diff（快照对比）、Baseline（预设 + 自定义）。
- 已确认的输入清单来源：沿用 T002 规格——15 个核心命令、7 个环境变量、密钥类只记存在性；发布版是否扩充清单待确认。
- 详细的逐项需求条目待 AC 与用户确认 v1 范围后补写。

### 6.2 用户场景与使用流程

以下为头脑风暴中的交互示意（讨论中，非最终定案）：

- 装机场景：`EnvDoctor check -Baseline python-ai` → 显示已安装进度与缺失清单 → 给出可复制的 winget 安装命令文本。
- 迁移场景：老机 `probe` 存快照 → 新机 `diff -With 老机.json` → 差异清单即装机清单。
- 审计场景：`check` 直接输出健康结论；`probe` 留档完整报告；`diff -Last` 查看距上次的漂移。
- 自动化场景：`check -Json` 与退出码约定（0 健康 / 1 告警 / 2 危险，讨论中）供 CI/AG 调用。

### 6.3 输入、处理与输出

- 输入：命令行参数（讨论中）：动词 probe/check/diff、`-Baseline`、`-OutputPath`、`-TimeoutSec`、`-Compare` / `-With`；可选外置配置文件覆盖默认探测清单。
- 处理：探测引擎（原始字节捕获 + 编码嗅探 + 超时控制 + 命中择优）→ 数据层（统一结构）→ 渲染层（终端 / Markdown / JSON 三层分离）。
- 输出：终端彩色摘要；Markdown 报告（路径表格含来源列、命令表格含状态列、环境变量表格，对齐 T002 规格的中文状态用词）；JSON 快照（字段保持英文稳定，带 `schema_version`，供 AG/程序解析及 WinMew 未来消费）。

### 6.4 异常情况与边界条件

以下各项均有诊断实证或已知技术风险，属发布前必须处理项：

- `wsl.exe` 等输出 UTF-16LE 的命令：统一以原始字节捕获后按 NUL 特征嗅探解码（已实证当前 V1/V2 均存在此缺陷）。
- 探测超时：所有 `--version` 及扩展探测（pip / npm / docker）统一超时保护，超时标注 [超时] 而非挂死。
- Docker 三态区分：未安装 / 已安装但 daemon 未运行 / 运行中，避免误报 0 容器。
- `where.exe` 命中择优：优先 .exe / .cmd；对无输出且非零退出的命中（如 Store 存根，实测退出码 49）自动尝试下一命中。
- PowerShell 兼容性：需在 Windows PowerShell 5.1 与 PowerShell 7 下行为一致（含 `Out-File` 编码差异、`.cmd` 调用差异）。
- 失效路径检测需绕开 `Test-Path -IsValid` 对非法字符（通配符、引号）判断不可靠的已知问题（PowerShell issue #21112）。

### 6.5 功能优先级与版本归属

| 层级 | 内容 | 性质 |

## 7. 非功能需求

- 性能：版本探测从现有 Start-Job 方案约 20 秒降至秒级（改用 Start-Process 原始进程并发等待）；具体指标待实现后实测确认。
- 稳定性：任何单条探测异常不得中断整体流程；全部探测有超时上限。
- 安全与隐私：只读红线；密钥类变量只记存在性不记值（沿 T002 约束）；无联网行为——处方仅生成 winget 命令文本，不代为执行。
- 易用性：下载即用（单文件）；报告语言（中文为主 / 双语 / 英文优先）待确认。
- 兼容性：Windows 10/11；Windows PowerShell 5.1 与 PowerShell 7 双兼容；最低支持版本待确认。
- 日志与诊断：约定退出码（0/1/2，讨论中）；关键异常在报告中标注原因而非静默吞掉。
- 安装、升级与分发：主渠道 GitHub Releases 提供单文件；辅渠道 PowerShell Gallery（Install-Script）；明确不做 exe 打包（杀软误报风险）；不申请 winget 收录（首版）。

## 8. 技术约束

| 项目 | 当前信息 |
|---|---|
| 目标平台 | Windows（PowerShell 环境） |
| 支持的 Windows 版本 | Windows 10 / 11（最低版本待确认） |
| 开发语言 | PowerShell（单文件 .ps1，内部按 配置区 / 探测引擎 / 判定规则 / 渲染器 分层） |
| UI 框架 | 无 GUI；终端输出 + 报告文件 |
| 系统信息获取方式 | `where.exe`、`[Environment]::GetEnvironmentVariable`、`Start-Process` 原始进程 + 字节级输出捕获（编码嗅探） |
| 软件身份识别方案 | 命令名 → where.exe 全量命中 → 择优（扩展名优先、存根检测） |
| 数据存储方式 | JSON 快照文件（`schema_version`）；快照目录按日期留档还是覆盖式待确认 |
| 是否需要联网 | 否（处方仅生成命令文本） |
| 是否需要 AI 能力 | 否 |
| 安装包与发布方式 | 单文件脚本；GitHub Releases 为主渠道，PSGallery 为辅渠道；不做 exe 打包 |

技术选型延续现有原型（PowerShell），不因发布而更换语言或引入运行时依赖；如后续需求超出 PowerShell 能力再行评估。
