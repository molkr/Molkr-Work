# Project Template

> 本目录是 `MolKr-Work` 通用项目资料模板。创建新项目时，复制本目录并重命名为项目名称。

## 项目基本信息

- 项目名称：
- 项目状态：需求探索 / 研究中 / 设计中 / 开发中 / 测试中 / 已完成 / 已暂停
- 项目负责人或执行代理：
- 最近更新：

## 项目目标

简要说明项目要解决的问题及预期成果。

## 当前进展

记录当前阶段和已完成事项。

## 当前任务

说明项目当前正在处理的主要任务；没有进行中的任务时填写“暂无”。

## 待解决问题

记录影响项目推进或需要决策的关键问题；没有时填写“暂无”。

## 下一步行动

明确下一步由谁完成什么；尚未确定时注明“待确认”。

## 目录说明

| 目录 | 用途 |
|---|---|
| `Tasks/` | AC/AG 任务交接、执行反馈与任务跟踪 |
| `PRD/` | 需求文档与产品需求规格 |
| `Research/` | 市场、竞品、用户及技术研究 |
| `Design/` | 产品、交互、流程与方案设计 |
| `Development/` | 技术架构、开发计划及实现说明 |
| `Testing/` | 测试计划、测试记录与验收报告 |
| `Logs/` | 关键决策、变更及阶段记录 |

## 协作约定

- 谁负责产出内容，谁负责起草并提交到对应目录。
- AC 负责需求统筹、方案讨论、审核和反馈；AG 按任务负责研究、设计、开发、测试及阶段成果。
- 每份正式文档应有明确的主要维护方，避免双方无协调地同时修改。
- 重要方向、范围和决策变更须先经用户确认。
- 更新已有文档前，先读取当前版本并确认没有覆盖对方尚未整合的修改。
- 具体协作流程遵循仓库根目录的《MK07_AC-AG 协作规范》。

## 文档状态与版本

正式协作文档应尽可能标注以下信息：

- 状态：Draft（草稿）/ Review（审核中）/ Approved（已确认）/ Archived（已归档）
- 版本：如 V0.1、V1.0
- 主要维护方：
- 最近更新：

状态用于区分文档成熟度，不等同于项目整体状态。尚未确认的草案不得作为已批准结论使用；不适合标注状态的简短记录可省略。

## 文件管理约定

- 项目协作文档优先使用 Markdown（`.md`）。
- 文件名使用英文或拼音，避免中文文件名。
- 同一份正式资料原则上只保留一个正式位置。
- 模板目录按项目实际需要使用；不适用的目录可以删除，不要求每个项目填满所有目录。
- 源代码原则上保留在项目自身的代码仓库或本地工作区；只有明确需要跨 AC/AG 共享的开发文档才放入本目录。
